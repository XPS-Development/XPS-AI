## 1. Вычислительное ядро и адаптер

- [x] Неизменяемые типы серии, шага, пика, исключения, связи, трека и результата.
- [x] Перенос continuous minimum-cost path cover из `ai-xps-series`:
  стоимость Huber, площади и ранги, глобальная оценка неоднозначности,
  прежние параметры по умолчанию; без ролей дублетов и связей через пропуски.
- [x] Ручные назначения и запреты как ограничения; проверка конфликтов.
- [x] Адаптер физических ComponentDTO: все области одного спектра в одном шаге,
  площадь через model.area(), FWHM только для симметричного pseudo-Voigt,
  причины исключений, сохранение пустых шагов и нулевых площадей.
- [x] Определения и расчёт показателей: исходные значения, разность энергий,
  сдвиг относительно ID опоры, суммы, отношения и проценты. Пропуски с причиной,
  перенос неоднозначности, отсутствие неявной подмены операндов.
- [x] Регрессии по зафиксированным результатам исходного алгоритма и тесты
  адаптера, ограничений, расчётов и граничных случаев; ruff, ty, pytest.

Реализовано в `core/post_processing/`: `types.py`, `adapter.py`, `matching.py`,
`metrics.py`; публичный API — `core.post_processing`. Объекты снимка содержат
только скаляры и кортежи; DTO, модели и массивы в worker не передаются.
Адаптер принимает плоскую последовательность физических компонентов всех
областей; сбор этой последовательности через query API относится к этапу 2.

Регрессии находятся в `tests/core/post_processing/`: 52 теста, включая семь
зафиксированных примеров исходного continuous-режима. В `regression.json`
записаны происхождение и SHA-256 исходного файла; соседний репозиторий для
запуска тестов не нужен. Дополнительно выполнено 100 сравнений с исходным
алгоритмом на случайных входах с seed=42, с нулевыми и ненулевыми весами
ширины/формы: связи, полная стоимость и оценки неоднозначности совпали.

Особенности текущего ядра:

- Ручная связь фиксируется даже за пределами автоматического окна энергии;
  её стоимость рассчитывается прежней функцией, margin отсутствует.
- Неоднозначность показателя переносится консервативно со всего используемого
  трека, включая трек на опорном шаге.
- Единица площади пока обозначается `area`: конкретную подпись физических
  единиц измерения нужно связать с метаданными при построении таблиц и экспорта.
- Настройки разрывов и роли дублетов отсутствуют в API; доли и ранги для
  стоимости берутся среди всех допустимых пиков шага.

успешны; общий pytest — **623 passed, 1 skipped** (Qt offscreen).

## 2. Состояние документа и приложение

- [x] PostProcessingUseCases: сбор снимка через query API, редактирование серий.
- [x] Change/Command/registry и UiRefresh; undo/redo всех сохранённых правок.
- [ ] Фоновый worker, отмена и проверка версии входа перед применением результата.
- [x] Отпечатки и устаревание; недоступные шаги при удалении спектра, восстановление undo.
- [x] Стабильные якоря треков, имена, конфликты ограничений и ссылок показателей.
- [x] Формат документа 1.1, чтение 1.0, round-trip, new/replace/append и коллизии ID.
- [ ] Единые проекции подробной и аналитической таблиц, CSV и описание расчётов;
  запрет обычного экспорта устаревшего результата.

Состояние хранится в `CoreCollection.post_processing` отдельно от дерева объектов;
все изменения серий применяются через `SetPostProcessingSeries` и соответствующую
команду. `PostProcessingUseCases` предоставляет создание, редактирование,
удаление, именование треков и подготовку/применение результата. Оркестратор
передаёт эти операции, QueryService возвращает неизменяемый DTO со статусами
доступности, устаревания, конфликтами и рассчитанными значениями.

Сериализация сохраняет полное состояние автоматически, без дополнительного
аргумента у вызывающего кода. Версия 1.1 включает секцию `post_processing`;
1.0 читается как документ без серий. JSON и gzip используют один кодек.
Загрузка валидируется во временных хранилищах; ошибка оставляет текущий
документ, метаданные и историю нетронутыми. При append исходные объекты
по-прежнему сохраняют существующие ID; коллизии ID серий разрешаются новым ID
и переназначением ID серии в её снимке. Несовпадение с фактическими исходными
данными проявляется как устаревание, без удаления старого результата.

Отпечаток включает порядок спектров, области, физические параметры моделей,
настройки и ограничения. Статусы вычисляются по текущему документу: undo
изменения/удаления автоматически восстанавливает актуальность и доступность.
Имена и настройки таблицы не меняют отпечаток. Якоря именованных треков
сохраняются при пересчёте; исчезновение/слияние именованных якорей требует
явного разрешения конфликта. Пропавшие операнды и опора не заменяются.

Для будущего worker уже готовы `prepare_post_processing` и
`apply_post_processing_result`: снимок содержит ревизию серии, отпечаток и
токен жизненного цикла документа. Устаревший результат отклоняется до записи
в историю. Сам worker и механизм отмены пока не подключены. Изменение ручных
ограничений сохраняет старый снимок как устаревший; пересчёт запускается отдельно.
Будущий CSV-экспорт должен проверять DTO.exportable перед записью.

**669 passed, 1 skipped**; ruff, format и ty проходят.
